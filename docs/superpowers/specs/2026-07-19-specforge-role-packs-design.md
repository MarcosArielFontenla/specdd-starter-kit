# SpecForge — Role Packs for the SpecDD Harness

**Date:** 2026-07-19
**Status:** Approved design, pending implementation plan
**Scope:** `specforge-kit` (wizard + generators + e2e + docs) and one row of the root
README. SpecDD, SpecDeploy, platform, and `packages/ui` untouched.

## Motivation

SpecForge today generates a standalone, pre-harness mini-scaffold: one persona per
run, a rules-rich `copilot-instructions.md` (exactly the drift the harness fights),
Copilot-only prompts, and a root `skills/` folder disconnected from `.agents/`. A
team using SpecDD + SpecForge ends up with two parallel systems in one repo — the
same problem the legacy-harness deprecation feature just solved.

New direction: **SpecForge generates Role Packs** — per-role extensions (BA / QA /
Dev / UX) that plug into a project scaffolded with the SpecDD Harness. SpecForge
becomes the natural complement of SpecDD instead of a parallel scaffold.

## Decisions made

| Decision | Choice |
|----------|--------|
| Direction | Role Packs for the Harness (not merged into the SpecDD wizard; not a cosmetic refresh). |
| Target ingestion | Optional. A "Target Project" step ingests the destination folder to detect its SpecDD Harness and compute collisions; skipping it yields a standard pack with canonical paths. |
| Scope | Project-scoped. Roles are durable; feature work belongs to the harness's spec-first pipeline. Feature title/slug/context fields and the governance step are removed. |
| Multi-role | One run generates any subset of BA/QA/Dev/UX (≥1 required). |
| Wiring the target | The pack never modifies existing ROUTING/REGISTRY (never clobber). Wiring ships as a pre-generated `role-pack-install.tasks.md` (`status: draft`, human approval gate) executed by the agent. |
| Collisions | Skip-and-report only. A role pack never replaces anything (no override mode). |
| Adapters / rules files | Not generated by SpecForge — adapters and the primer are SpecDD's job. The rules-rich `copilot-instructions.md` is gone. |

## Wizard UX (7 steps, replaces the current 6)

```
1. Welcome
2. Target Project     optional folder ingest (webkitdirectory, same privacy note:
                      100% in-browser). Detects the target's SpecDD Harness
                      (.agents/REGISTRY.md, or AGENTS.md + .agents/orchestration/
                      ROUTING.md). Detected → confirmation card. Not detected →
                      non-blocking notice: "generate the harness first with the
                      SpecDD wizard". Legacy non-SpecDD harness signals → notice:
                      "migrate it first with SpecDD Brownfield". Skippable.
3. Roles              multi-select BA / QA / Dev / UX; at least 1 required
4. Role Options       conditional: QA approach (manual/automated) if QA selected;
                      Figma toggle if UX selected
5. Skills             the kit's 36 playbooks, grouped by selected role
6. Tools              multi-select (same list as SpecDD); ONLY controls the Copilot
                      projection — at least 1 required
7. Preview / Download groups: Role pack / Copilot projection / Skipped
```

## Generated Role Pack (per selected role, e.g. QA)

```
.agents/skills/role-qa/SKILL.md          harness-format skill: frontmatter with
                                         snapshotPath/snapshotVersion/driftPolicyPath
                                         pointers; Scope of the role; Must rules and
                                         Never do derived from the current persona
                                         guardrails; Verification; Playbooks index
.agents/skills/role-qa/assets/*.md       selected kit playbooks, verbatim
.agents/evals/rubrics/role-qa.yaml       log_only / median / ciFailConsecutiveWindows: 2
.agents/workflows/role-qa/<command>.md   persona commands (testcases, validate, …)
                                         rewritten as vendor-neutral workflows (no
                                         Copilot frontmatter); QA gains the playwright
                                         workflow when approach ≠ manual, UX gains the
                                         figma setup workflow when the toggle is on
.agents/subagents/role-qa.agent.md       canonical subagent definition (seed for the
                                         Multi-Agent system, which STAYS inactive —
                                         stated explicitly in the file)
--- cross-cutting (once per pack) ---
.agents/specs/tasks/role-pack-install.tasks.md
                                         pre-generated, status: draft, human gate:
                                         per-role ROUTING/REGISTRY/budget-manifest rows
                                         (primer stays ≤40 lines) + verification phase
                                         running validate-spec.ps1 and validate-budget.ps1
context/role-pack-report.md              what was generated, whether a harness was
                                         detected, skipped collisions, agent kickoff
                                         (approve the install tasks, then execute)
.github/prompts/specforge-*.prompt.md    ONLY when GitHub Copilot ∈ tools — a
                                         projection referencing the pack's workflows
```

## Implementation architecture

- **Lightweight ingestion, no analyzer duplication**: SpecForge needs neither stack
  detection nor suggestions. New `TargetStep.jsx` (folder input) plus a pure
  `detectTargetHarness(paths)` util (~20 lines): SpecDD harness = `.agents/REGISTRY.md`
  present, or root `AGENTS.md` + `.agents/orchestration/ROUTING.md`; legacy harness
  signals mirror the SpecDD detector's path list (`.agents/**`, `SYSTEM_PROMPT.md`,
  etc.) for the "migrate first" notice. Kits stay independent (repo pattern:
  deliberate minimal duplication; extract to `@specdd/ui` only at a third copy).
- **Rewritten generators** (pure functions): `renderRoleSkill(role, selectedSkills)`,
  `renderRoleRubric(role)`, `renderRoleWorkflow(role, cmd, input)`,
  `renderRoleSubagent(role)`, `renderInstallTasks(input)`, `renderPackReport(input,
  skipped)`. `promptsFor` survives to drive both workflows and the conditional
  Copilot projection. The kit's 36 skill files ship verbatim as role `assets/`
  (the existing `bundle-skills.js` keeps bundling them; only output paths change).
- **Wizard model**: `{ targetPaths: string[], harness: { specdd: boolean, legacy:
  boolean }, roles: string[], qa, ux, skillsByRole, tools: string[] }`. Validation:
  ≥1 role, ≥1 tool. Steps computed from selected roles (Role Options appears only
  when QA or UX is selected).
- **Collisions**: with an ingested target, any pack path present in `targetPaths` is
  dropped from the ZIP and listed in the Skipped preview group and the pack report.
  `context/role-pack-report.md` itself is exempt (always emitted).
- **Confidentiality**: the same generated-content version-tag guard test pattern used
  in specdd-kit is added to SpecForge's `generators.test.js`.

## Testing

- Unit: `detectTargetHarness` (SpecDD present / absent / legacy-only); one test per
  role artifact renderer (frontmatter pointers, rubric `log_only`, workflow free of
  vendor vocabulary, subagent carrying the inactive note); install tasks with real
  per-role rows; collision skip + report; Copilot projection on/off; multi-role run
  (2 roles → 2 complete sets); version-tag guard over all generated output.
- E2E (Playwright): (1) standalone multi-role walkthrough to ZIP download;
  (2) ingest walkthrough with a minimal SpecDD-harness fixture (`.agents/REGISTRY.md`
  + `.agents/orchestration/ROUTING.md`) asserting the detection card and the Skipped
  group. The current SpecForge e2e is rewritten (the flow itself is the feature).
- Docs: `specforge-kit/README.md` + `SETUP.md` updated to the Role Pack model; root
  README's specforge row updated; `docs/Agentify_Wizard_Structural_Spec.md` marked
  superseded (kept as history).

## Out of scope

Activating the Multi-Agent system (subagent files are canonical seeds; activation
stays trigger-gated), org profiles (ROADMAP item 2), Jira/Azure DevOps integrations,
merging SpecForge into the SpecDD wizard, and any change to SpecDD, SpecDeploy,
platform, or `packages/ui` beyond the root README row.

## Confidentiality constraint (carried over)

No committed content references private harness source documents by filename or
version label; the architecture is the **SpecDD Harness** with its own versioning.
