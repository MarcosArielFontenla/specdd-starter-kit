# specdeploy-kit

Infrastructure-agnostic **deploy wizard**: collects your app's build info, a deployment
target and CI/CD choices, then generates a ZIP with everything needed to deploy —
pipeline (GitHub Actions / Azure Pipelines), IaC, a step-by-step runbook, a `specdeploy.json`
manifest and `.env.example`.

> It generates artifacts. It never deploys, never runs a backend, never touches credentials.
> Generated pipelines reference secrets **by name only**.

## Providers (v1)

| Provider | CI | API support | IaC |
|----------|----|-------------|-----|
| Azure Static Web Apps | GHA + AzP | ✅ managed Functions | Bicep |
| Cloudflare Pages | GHA + AzP | — | — |
| AWS S3 + CloudFront | GHA + AzP | — | Terraform |
| Vercel | GHA | — | — |
| Netlify | GHA | — | — |
| On-prem Docker (Nginx/IIS) | GHA + AzP | ✅ Node sidecar | docker-compose |

Providers are **data, not code**: a folder under `providers/` with a `provider.json`
descriptor + templates. Adding one requires no wizard changes — see
[`docs/provider-authoring.md`](docs/provider-authoring.md).

## Quick start

```powershell
npm install                        # once, at the repo root (npm workspaces)
npm run dev -w specdeploy-wizard   # serves on :4323
```

Open http://localhost:4323, complete the 6 steps, download the ZIP and extract it at the
root of the project you want to deploy. Then follow `docs/deploy-runbook.md` inside the ZIP.

## Optional delivery contract and graph (Phase 10 A2)

In **CI/CD**, enable **Export delivery contract and graph (draft only)**. It is off
by default. Enter a canonical project ID, repository ID, full source commit hash
(40 or 64 lowercase hex characters), and distinct staging/production destination
IDs. These are explicit logical references, not URLs, secrets or created resources.

Review and download add five files under `delivery/`: `provider.json` (hashed
provider snapshot), `definition.json`, `control-plane.json`, `projection.json` and
`README.md`. The existing ZIP files and their contents remain unchanged, including
when the option is disabled. Download uses the same generated bytes as the preview.

Every delivery graph is **draft and not executable**. No provider has a controlled
delivery runtime adapter yet. Existing pipelines do not implement these graph
protections; activating them can still cause their legacy external actions. The
environment selector, approval checkbox and security acknowledgement do not grant
promotion approval. The source hash is not proof of merge. Supply the referenced
Project Definition, Harness and eval definitions separately before any future run.

No Warp account, credentials, environment creation, merge or deployment is needed
to generate these artifacts. A separate [fixed local rehearsal](../packages/delivery-model/)
can materialize a fixture and run HTTP smoke checks through an approval pause;
it does not execute these exported provider graphs.

For programmatic use, `generateFiles(bundle, input)` retains the legacy synchronous
API. `await generateFilesWithDelivery(bundle, input)` adds delivery artifacts only
when `input.delivery.enabled` is true. It validates the explicit delivery inputs,
uses Web Crypto locally and rejects output collisions.
